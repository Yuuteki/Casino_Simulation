# 二十一点灰盒场景与模型接入规范 v0.1

> 文档定位：为后续建模、场景替换和表现层接入提供稳定约定。本文只描述二十一点灰盒桌与模型锚点，不改变二十一点规则、筹码规则或 MVP 范围。

## 1. 当前目标

当前灰盒场景用于让本地二十一点 MVP 从纯屏幕 UI 过渡到可打开、可替换模型的 Unity 场景。它不是最终牌桌房，也不包含落座 CG、可旋转座位镜头、最终动画或好友联机。

场景文件路径：

```text
Assets/Casino/Scenes/BlackjackGreybox.unity
```

生成器路径：

```text
Assets/Casino/Editor/BlackjackGreyboxSceneBuilder.cs
```

## 2. 设计边界

- 不在场景物体上实现或修改二十一点规则。
- 不让动画、模型碰撞或物理结果决定发牌、下注、胜负或结算。
- 规则对象仍由 `Casino.Blackjack` 和本地会话驱动；场景物体只是锚点、占位模型和表现容器。
- 美术模型可以替换占位体，但应保留本规范列出的关键 GameObject 名称或等价锚点。
- 当前灰盒只服务本地 MVP。好友 Host/Client、落座 CG、完整座位镜头和牌桌房仍是后续里程碑。

## 3. 单位与朝向

- Unity 1 unit 按 1 米处理。
- 二十一点桌中心位于世界原点附近。
- 本地玩家默认在画面下方，即 `Seat_0_Local`。
- 庄家在桌子远端中央，面向本地玩家方向。
- `Y` 轴向上，桌面可交互展示区域约在 `Y = 0.85` 到 `Y = 0.95`。

## 6. 庄家锚点

庄家分组下必须保留：

```text
Dealer/Dealer_Anchor
Dealer/Dealer_CardZone
Dealer/Dealer_HoleCardZone
Dealer/Dealer_ChipTray
Dealer/Discard_Tray
```

用途：

| 锚点 | 用途 |
| --- | --- |
| `Dealer_Anchor` | 庄家身体、手部动画或庄家头像的默认根位置 |
| `Dealer_CardZone` | 庄家公开牌展示区域 |
| `Dealer_HoleCardZone` | 庄家暗牌展示区域 |
| `Dealer_ChipTray` | 赌场筹码托盘、收付筹码动画起点 |
| `Discard_Tray` | 弃牌堆和洗牌前回收牌的表现位置 |

## 7. 六个玩家座位

当前六个座位为：

```text
Seats/Seat_0_Local
Seats/Seat_1_LeftNear
Seats/Seat_2_LeftFar
Seats/Seat_3_FarLeft
Seats/Seat_4_FarRight
Seats/Seat_5_RightNear
```

每个座位下必须保留：

```text
Seat_Placeholder
AvatarAnchor
CameraAnchor
CardZone
BetSpot
ChipStackAnchor
ActionPromptAnchor
```

用途：

| 锚点 | 用途 |
| --- | --- |
| `Seat_Placeholder` | 椅子或座位占位体，可替换为模型 |
| `AvatarAnchor` | 玩家低细节身体、手部和头部模型根位置 |
| `CameraAnchor` | 后续座位视角的默认相机位置参考 |
| `CardZone` | 该座位玩家手牌展示区域 |
| `BetSpot` | 主下注筹码堆位置 |
| `ChipStackAnchor` | 派奖、收筹码和筹码堆表现位置 |
| `ActionPromptAnchor` | 轮到该座位行动时的桌面提示位置 |

真实联机座位编号未来仍由应用层维护。不同客户端可以把自己的真实座位映射到本地 `Seat_0_Local` 的表现位置，但这属于后续表现逻辑，不改变规则座位编号。

## 8. 美术模型接入建议

建议后续建模资产放在：

```text
Assets/Casino/Art/Models/Blackjack
```

建议后续二十一点预制体放在：

```text
Assets/Casino/Prefabs/Blackjack
```

模型要求：

- 先以低面数、低细节风格完成清楚轮廓，不追求写实材质。
- 牌、筹码、下注区域和点数信息优先保证可读性。
- 桌面模型不应依赖物理碰撞决定卡牌或筹码位置。
- 模型 pivot 建议位于物体底部中心或锚点根部，便于替换占位体。
- 尺寸先贴合灰盒比例，后续如要改桌面大小，应同步检查六个座位、牌区、下注点和相机锚点。

## 9. 后续接入顺序

1. 用真实桌子、椅子、筹码盘和弃牌盘模型替换占位体。
2. 保留锚点并接入牌、筹码和手牌视图对象池。
3. 把现有屏幕 UI 逐步拆成常驻 HUD 和桌面附近提示。
4. 加入本地座位相机控制，但只允许旋转，不允许自由移动。
5. 在规则状态稳定后，再制作落座 CG 和完整牌桌房。

## 10. 验收

场景契约由 EditMode 测试保护：

```text
Assets/Casino/Tests/EditMode/Presentation/BlackjackGreyboxSceneContractTests.cs
```

如果关键锚点被重命名或删除，测试会失败。需要更改层级时，应先更新本文档，再同步更新测试和引用代码。
